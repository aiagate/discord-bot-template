既存ユーザーのプロフィールを更新・取得できるようにしてください。

要件:
- 既存の User に display_name と bio からなるプロフィールを持たせます。display_name は既存の値と検証規則を引き継ぎ、別の表示名を重複管理しません。
- bio は文字列で0〜500文字。空文字を許可し、空白と改行は入力どおり保持します。上限超過はエラーです。
- 既存のユーザーIDを指定して display_name と bio の両方を更新します。未知のユーザーIDでは新規ユーザーを作らず、既存のエラー契約に従います。不正入力や保存失敗で部分的な更新を確定させません。
- 既存の FastAPI users router に PUT /users/{user_id}/profile を追加します。JSON は display_name と bio の両方を必須とし、成功結果は既存の更新操作の流儀に合わせます。既存の GET /users/{user_id} の結果に bio を追加して、保存したプロフィールを取得できるようにします。
- 既存のユーザー作成の入力と挙動は維持し、新規ユーザーと移行前から存在するユーザーの bio は空文字にします。メールアドレスやIDはプロフィール更新で変更しません。
- DBに永続化し、別の Unit of Work で再読込しても同じプロフィールを取得できるようにしてください。必要なマイグレーションとテストを追加してください。
- 認証・権限、Discord/LINE側の入口追加、検索、画像、プロフィール専用の外部サービスは今回の範囲外です。

リポジトリの AGENTS.md と関連ドキュメントを読み、既存のアーキテクチャと実装パターンに従って、最小限の変更で実装してください。`.agents/skills` があれば関連する SKILL.md を確認してください。実装後に適用可能な品質チェックを実行し、変更内容、実行したチェック、その結果、残る制限を報告してください。
